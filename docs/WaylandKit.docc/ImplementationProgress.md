# Implementation progress and open delivery gates

Separate implemented baseline functionality from measured acceptance and deferred work.

## Current delivery state

WaylandKit now has public client-first, client, server, protocol, runtime, cursor, EGL, and utility products. The baseline is Swift 6.4.2 and libwayland 1.26.0 on x86_64 Linux. The core implementation and its independent native tests are present. The complete delivery gate remains open because the initial 10% typed-throughput budget has not passed and human review is outstanding. aarch64 remains explicitly deferred.

| Phase | Implemented evidence | Remaining boundary |
|---|---|---|
| 0: design review | Ownership/state model, unsafe contracts, source audits, repository policy, recorded implementation decisions | Human review of the current patch |
| 1: compiler and ABI | Exact x86_64 compiler/ABI experiments; strict safety; positive/negative production API compilation | Deferred aarch64 |
| 2: ownership runtime | Authoritative records, invalidation, dependency order, deferred release, descriptors, stable contexts, native destruction, cached admission and close notification | Twenty-five production bridge allocation/initialization failures pass isolated ASan/UBSan; broader native allocator failpoints remain separate and fatal allocator termination is excluded |
| 3: client | Named/FD connections, typed constructors/destructors, queues, prepare/read/cancel, generation tokens, cross-queue pending bound, poll cancellation/backpressure faults, copied protocol errors | Optional asynchronous coordinator is not exposed |
| 4: server | Display/client/resources, globals/withdraw/filter, root-managed accepted clients, snapshots/destruction notification, logger, removable sockets, serials, persistent fd/timer/unsafe signal sources, run/terminate | Foreign listener/reader integration stays explicitly unsafe |
| 5: generator and baseline mapping | 23 interfaces/134 messages, both directions, all ordinary wire arguments, scanner equivalence, deterministic generation, native ABI/field checks, explicit declaration/macro mapping | Imported XML/schema generation, owned sealed arenas, managed dynamic extension client/server resources, and imported server globals are implemented; generated typed extension facades compile and pass lifecycle round trips; broader extension runtime coverage remains gated |
| 6: advanced APIs | Checked cursor/image/buffer ownership after unsafe trusted file loading, unbound EGL windows, explicit SHM refs and snapshots, managed process logs, guarded native byte arrays, unsafe/legacy compatibility | Arbitrary native parser inputs and long-lived foreign EGL attachment are unsafe integration boundaries |

## Native and protocol coverage

The native inventory contains 1,535 identity-deduplicated items: 452 functions, 23 data symbols, 82 records, 181 fields, 30 enums, 238 enum members, 15 typedefs, 380 macros, and 134 protocol messages. All are classified. The compatibility generator emits 1,401 explicit native mappings, including documented C-only preprocessing controls. Source imports alone do not count as a mapping. Each executable native mapping has a generated alias or adapter; field aliases compile, 964 layout/constant comparisons run against C, every union projection has a native-produced value test, and all nine arbitrary-layout iterator/container macros have runtime fixtures.

The inventory's 168 implemented high-level entries count 34 function mappings and 134 protocol messages. Other entries distinguish unsafeABI and cOnly rather than claiming a safe facade for every raw C operation. coverageGatePassed=true describes complete mapping classification/availability. releaseGatePassed=false keeps performance, review, and architecture evidence separate.

Independent native C peers exercise 69 ordinary requests and 58 ordinary events through both client and server bindings. Nullable arguments run both variants. The seven reserved display/registry messages retain libwayland's native implementation and have registry, sync, error, ID-management, bind, withdrawal, and global integration coverage. These fixtures verify wire representation and ownership, not every compositor protocol-state policy.

## Public metadata authority

Public protocol conformance cannot supply native metadata. Exact generated marker metatypes select canonical immutable schemas before native acquisitions. External conformances fail with unsupportedMarker without executing a name getter or decoder. Core descriptors remain process-lifetime native storage. Imported schemas can now construct bounded owned arenas, including cyclic definitions. Managed dynamic client and server-resource factories pin imported metadata in their cleanup contexts; raw custom native consumers require explicit unsafe retention. See <doc:OwnedProtocolMetadata>.

## Quantitative performance

Scripts/benchmark-typed.py compares identical wl_data_offer.action scalar send/read/dispatch work against a native C peer. Setup, warmup, and root teardown are separated. Throughput uses three pinned-CPU process runs with nine alternating C/Swift pairs each; per-process losses remain in the report because within-process samples are correlated. The 10% throughput gate requires both aggregate and every process-level loss to meet the budget for both batch sizes. Throughput runs without allocation interception; a separate glibc-entry pass reports allocations, and separate clock-instrumented passes report batch p50/p95/p99 and send, prepare/read, and dispatch totals. Phase timings use the legacy split Swift read and dispatch path and are diagnostic because timing calls perturb the measured loop. A separate nine-pair callback-isolation pass compares the same C peer with native C and raw Swift dispatch callbacks while omitting WaylandKit ownership and typed decoding. The raw Swift callback differs from the C callback by approximately 0% in the current run; this supports investigating typed ownership and decoding as the source of the larger measured gap, but does not prove an individual hotspot. A raw Swift read/dispatch diagnostic uses the same raw Swift callback on both sides and differs from the C read/dispatch loop by 1.21% for single-message reads and approximately 0% for batch-64 in the latest run. It omits WaylandKit ownership and adds one C-to-Swift entry per batch; the result points toward the ownership and typed paths as the larger source of overhead but does not isolate a specific instruction. A second diagnostic pass cancels typed delivery after warmup while keeping callback admission and mandatory disposal active. Its batch-64 loss fell from about 28% to 22% when ownership-free events stopped scanning their argument schema. Direct typed context implementation userdata then reduced batch-64 typed loss to approximately 22% in repeated runs while keeping retained dispatcher userdata as the context owner. Attachment now validates all native event names and expanded signatures before generated core unsigned getters use their fixed wire indices; the remaining getter kinds retain ordinary checks. A tri-state native callback check keeps canceled delivery on the admitted fast path; the diagnostic canceled batch-64 loss is approximately 16–17%. Package-generated core overloads now bypass the ownership reader for events containing only fixed-size scalar fields and combine scalar decoding with user delivery in one generated closure. Subscription installation precomputes schema eligibility, so the hot scalar callback bypasses repeated version and ownership checks. Earlier single-process batch-64 results ranged from roughly 17% to 22%; the current three-process aggregate remains above the quantitative gate. The ordinary typed delivery remains above the 10% budget; canceled delivery performs different handler work and is not a substitute for that gate. Reports include compiler, CPU affinity, source hashes, CPU time, root-close time, and empirical paired bootstrap intervals. The scalar fixture does not cover the full performance plan. String payload-size scaling, array, FD-passing, queue-coordination, SHM, and representative compositor performance measurements remain missing. The zero-argument wl_surface.commit request fixture now runs three pinned-CPU processes with nine alternating C/Swift pairs each. Both paths flush and drain each batch and verify the exact peer request count. The earlier aggregate request losses were 11.78% for batch 1 and 39.99% for batch 64. Their empirical paired-bootstrap 95% intervals are 11.00–12.17% and 39.73–40.22%. Within-process samples are correlated, so these intervals are diagnostic and do not replace the per-process gate. An earlier batch-1 aggregate was below 10%, but the repeated measurement is not; stable acceptance remains unproven. Endpoint creation precomputes a bounded opcode mask for version-supported nonterminal empty-signature requests. These requests marshal a null argument array directly after per-call lifetime and connection-error checks; other empty-signature encoder calls use initialized scoped stack storage instead of allocating a C argument arena. A separate glibc allocation-entry pass observes 60,000 entries for 20,000 requests in both C and Swift at each batch size, giving zero additional entries per request. These include native marshal and peer dispatch allocations; they do not imply an allocation-free native path. A separate 20,000-request clock-instrumented pass now records batch p50/p95/p99 for marshal, flush, and peer dispatch. The final batch may be partial. These quantiles are not per-request or compositor presentation latency. The aggregate throughput gate requires scalar delivery, zero-argument requests, and fixed-string requests to pass. The aggregate report lists these gaps separately from the scalar throughput and allocation gates; passing those two scalar gates alone cannot complete Phase 7.

Current measurements show zero additional glibc allocation entries per scalar event after warmup, but 15.94% throughput loss for single-message reads and 16.52% for batch-64 delivery in the latest three-process aggregate. Exact values depend on the report's input hashes and run. This fails the initial 10% hypothesis. Read-token allocation was removed, callback admission reuses the outer native frame, prepared-read validity avoids redundant domain entry, and one C call checks native-frame identity with the pending-close mailbox. Native access now claims the domain and validates the handle under one mutex acquisition. Matched handles check the monotonic live lifetime inside that lock without a per-access record dictionary lookup; absent lifetime metadata retains the authoritative lookup, while mismatched metadata is rejected. Callback delivery's uncontested path checks frame identity, pending closure, and cancellation in one C call. Scalar events classified ownership-free by both native and Swift metadata skip the terminal C signature scan; FD and new-proxy events retain it. Its admitted frame defers cleanup until native work completes. The combined default-queue read and dispatch call shares one admitted native frame. Pending closes remain synchronized and live-generation guards remain enforced. Domain exit skips the drain routine when the synchronized ready queue is empty; the locked mailbox recheck still observes a close posted before domain release. Empty admission mailboxes avoid redundant notification writes; repeated close requests do not leave a notification set without pending work. The budget has not been raised and checks have not been disabled. The benchmark gate therefore remains open.

## Reproduction and deferred scope

Run `python3 Scripts/validate.py --native-sanitizers --soak --benchmark`. The aggregate preserves command completion separately from measured throughput acceptance and exits unsuccessfully when that quantitative gate fails. The client display retains published arenas through native queue release. The pinned libwayland 1.26.0 source itself leaks queued child proxies and destroyed-object argument references in four independent C reproductions, including failed object lookup after constructor creation. A local patch passes these four ASan/UBSan cases in an isolated build, but is neither installed nor fully reviewed. A separate ordinary build of the patched source also passes all 26 upstream Meson test executables. This regression run uses tests and scanner enabled, documentation and DTD validation disabled; it does not add sanitizer coverage or establish upstream acceptance. Scripts/verify-native-pending-constructors.py now repeats this regression run and requires all 26 tests to pass without skips. Selected test results are recorded in .build/native-pending/report.json and the command log is retained at .build/native-pending/upstream-tests.log. The aggregate native baseline leak gate therefore fails. Generated typed extension facades now exist. A separate-package xdg-shell consumer now exchanges xdg_wm_base ping/pong, xdg_positioner construction and set_size, plus core wl_surface and xdg_surface/xdg_toplevel configure/ack with an independent C server. It verifies child-first destruction and zero retained Swift records at shutdown. Comprehensive xdg-shell runtime coverage and optional asynchronous delivery remain separate work. Real GPU integration requires its separate unsafe foreign lifecycle contract. Broader native allocation fault injection, human review, and deferred aarch64 remain explicit follow-up boundaries.
